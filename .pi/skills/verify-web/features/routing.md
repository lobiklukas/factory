# Routing

**Status: passing.** `/` redirects to `/sessions`, each section route renders inside the rail's
frame, and a session id that the control plane could not have minted is refused in the route rather
than sent to the API.

## Sub-features

- `/` redirects to `/sessions`: it is the only section with a real read behind it, and a redirect
  beats an empty first impression
- `/sessions` renders the list beside the pane; `/sessions/<id>` attaches to that session
- `/sandboxes` and `/approvals` render an honest empty state naming the milestone (M4, M3) that will
  back them, not a table with no source
- `/sessions/not-a-real-id` is refused by the route's `Schema.decodeUnknownOption(SessionId)`, so the
  pane says what a session id is instead of surfacing a `not_found` the user cannot act on
- Every route renders inside the same frame: a 48px icon rail, then the route

## How to get to it (user POV)

Open the dashboard root. No auth, no query parameters, no seed data.

## Driving it with drive.mjs

`drive.mjs` asserts the redirect, the copy on `/sandboxes` and `/approvals`, and the bad-id refusal.
The empty-state assertions are deliberately on the copy: a table appearing without a source behind it
fails the run.

## Gotchas

- The empty-state copy is asserted by the driver, so it is load-bearing. `No sandboxes yet` + `M4`,
  `No approvals pending` + `M3`, and `Not a session id this control plane mints` must survive an edit.
- `src/routeTree.gen.ts` is generated by the Vite plugin and committed, because `tsc` reads it. Adding
  a route file regenerates it; deleting the route file restores it, so a scratch route leaves no diff.
- `/sandboxes` and `/approvals` are named gaps, not features. See the feature map's gap list.
